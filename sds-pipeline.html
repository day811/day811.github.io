// 01 — contexte
Sport Data Solution

La mission

Sport Data Solution souhaite valoriser l'activité physique de ses collaborateurs via deux avantages : une prime de 5% du salaire brut pour les trajets domicile-travail en mobilité douce, et 5 jours bien-être annuels pour les salariés pratiquant au moins 15 activités par an. La mission : concevoir le POC du pipeline de bout en bout — de l'ingestion des données RH au dashboard décisionnel.

// 05 — fonctionnalités clés
POC

Ce que le pipeline sait faire

🔐
Chiffrement RH Fernet
Données personnelles (noms, adresses) chiffrées dès l'ingestion via Fernet (AES-128). Clé injectée via variable d'environnement. Déchiffrement uniquement en couche Gold pour la restitution Slack.
📍
Géocodage & validation déclarations
Calcul automatique de la distance domicile↔bureau via Google Maps. Validation des déclarations de transport : marche ≤ 15 km, vélo/trottinette ≤ 25 km. Alerte Slack en cas d'incohérence.
✅
Qualité WAP (Great Expectations)
Pattern Write-Audit-Publish sur 3 flux (RH, sports, activités). Deux niveaux : FAILED stoppe le pipeline, WARNING alerte Slack et supprime la ligne fautive. 11 checks RH + 6 checks activités.
🧠
Enrichissement IA (Gemini RAG)
Chaque activité sportive génère un commentaire de coaching personnalisé via Gemini 3 Flash. Réponse JSON pure pour réinjection directe. Fingerprint SHA pour détecter les doublons et modifications.
⚡
CDC temps réel (Debezium)
Debezium écoute les WAL de PostgreSQL et convertit chaque INSERT/UPDATE en message JSON avec enveloppe Before/After vers Redpanda, sans impacter les performances de la base source.
🏭
Simulation réaliste des activités
Générateur Python (Faker + Power Law) simulant 12 mois d'activités pour 161 employés. 85% de cohérence avec le sport déclaré, distribution exponentielle pour l'adoption progressive des inactifs.
📊
Power BI — Dynamic Bonus
Connexion directe Delta Lake via DeltaLake.Table() et PowerQuery. Paramètre What-if permettant aux RH de simuler différents taux de prime (5% → 10%…) sans toucher au pipeline.
📡
Monitoring Prometheus + Grafana
Supervision temps réel de la volumétrie Redpanda et de l'état des jobs Spark. Alerting proactif sur seuils critiques. Stack de monitoring intégrée dans le réseau Docker sport-pipeline.

// 07 — stack technique
choix justifiés

Technologies utilisées

Composant Technologie Justification
Orchestration Kestra Pilotage Python, SQL, plugins Slack/GSheet, gestion erreurs via subflows notify
Bus de messages Redpanda 23.3 Compatible Kafka API, plus léger en Docker, topics cdc.public.* dédiés par entité
CDC Debezium 2.4 Écoute WAL PostgreSQL, enveloppe Before/After JSON, zéro impact sur la base source
Streaming & calcul Apache Spark 3.5.3 Structured Streaming sur Redpanda, calcul distribué éligibilité + année sociale
Stockage Gold Delta Lake Transactions ACID, Time Travel pour audit des primes, format Parquet pour Power BI
Qualité données Great Expectations Pattern WAP, deux niveaux WARNING/FAILED, intégré dans les flows Kestra
IA coaching Gemini 3 Flash Réponse JSON pur configurable, RAG avec fingerprint SHA pour déduplication
Base opérationnelle PostgreSQL 15 wal_level=logical pour CDC, couche Bronze, source de vérité transactionnelle
Monitoring Prometheus + Grafana Métriques Redpanda, Kestra et Spark. Alerting sur goulots d'étranglement
Restitution Power BI DeltaLake.Table() natif, paramètre What-if pour simulation taux prime sans pipeline
Sécurité RH Fernet (cryptography) Chiffrement AES-128 des PII dès l'ingestion, clé injectée via .env
